# KirinYT 1.9.5 Beta

Pre-release · 14 October 2026

## Bilibili: fix empty playback responses

- Keep playable video and audio from the webpage when Bilibili's playback API reports success but returns no stream URLs. Previously, an empty API payload could replace valid webpage formats and end with **No video formats found**.
- If a signed-in webpage contains playback metadata without any stream URLs, allow the normal API fallback to run instead of treating that page response as complete.
- Load the bundled Bilibili extractor when fetching metadata, opening the format picker and processing mixed URL batches, as well as during downloads. Supports `bilibili.com` and `b23.tv` links.
- Refresh Bilibili format lists instead of loading an old cached info.json. Other sites retain their existing cache behavior.
- When neither the webpage nor the API provides playable streams, show an actionable Bilibili error without an endless retry loop.

## Keep interrupted-download recovery

- Preserves the Bilibili backup-CDN recovery introduced in 1.9.4-beta, including format IDs, cookies, selected downloader and partial files.
- Includes regression coverage for an interrupted video resuming from an API-provided mirror, keeping the completed audio and merging both tracks.

## Validation

- 13 offline Python engine regressions cover real upstream extraction with empty API/page responses, guest and signed-in selection, legacy fragments, plugin loading and interrupted transfers.
- Android unit tests cover mixed-site format batches, preserving request options, bounded recovery and non-retryable failures. Both release workflows run the engine and Android tests before building signed APKs.

The reported video is `BV16m421g7iL?p=1`. Its format lookup failed during the initial live check and returned playable streams in a later check; real-device behavior still needs confirmation on the user's connection. This patch does not bypass Bilibili account or regional restrictions.
