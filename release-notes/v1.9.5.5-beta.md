# KirinYT 1.9.5.5 Beta

Pre-release · 24 October 2026 (MYT)

## Bilibili download recovery

- Download native HTTP streams in ranges of at most 4 MiB to reduce reliance on long uninterrupted CDN responses. Existing partial downloads retain yt-dlp's resume handling.
- Treat incomplete and empty stream responses as retryable failures. Exhausted retries return control to CDN recovery instead of repeating an empty range indefinitely.
- Keep the last available backup when video and audio expose different numbers of mirrors. A later attempt no longer returns the shorter list to its failed primary server.
- Preserve selected formats, rate limits, external downloader preference and explicit `--http-chunk-size` settings, including `0`.

## Validation

- All 30 Python engine regressions passed locally on yt-dlp `2026.8.19` and `2026.10.21`, covering interrupted transfers, HTTP 503, bounded ranges, exact file integrity after resume, unequal backup lists and merged audio/video.
- All 23 Kotlin recovery/format tests passed locally in an isolated JVM with platform stubs. The release workflow runs the Android unit tests before building and checks APK signatures before publication.

The live Bilibili page returned HTTP 412 in the build preparation environment. The reported public transfer has not been verified on the user's network; this update does not guarantee CDN speed or repair previously incomplete output files.
