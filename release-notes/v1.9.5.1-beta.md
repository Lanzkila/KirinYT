# KirinYT 1.9.5.1 Beta

Pre-release · 14 October 2026

## Bilibili: fix No video formats found

- Keep usable video and audio from the webpage when Bilibili's playback API reports success but returns no stream URLs. An empty API payload previously could replace valid webpage formats.
- Allow the normal API fallback when a signed-in webpage contains playback metadata without stream URLs.
- Load the bundled Bilibili extractor during metadata lookup, format selection, mixed URL batches and downloads, including `b23.tv` links.
- Refresh Bilibili format lists instead of reusing cached info.json playback data.
- Preserve working legacy formats when another optional quality has no streams.
- Show a clear error if neither source has playable streams, with bounded retries.

## Existing recovery

Keeps the 1.9.4-beta interrupted-download recovery: API-provided backup URLs, selected formats, cookies, downloader and partial files are preserved.

## Validation

- 14 Python engine regressions cover empty page/API responses, signed-in and guest selection, optional legacy qualities, plugin loading, and interrupted video recovery followed by video/audio merging.
- Six Android unit tests cover plugin setup for mixed batches, request preservation, bounded transfer retries and non-retryable failures.
- The reported video `BV16m421g7iL?p=1` returned 15 formats with the patched extractor, selecting `100026+30280`. Small video and audio samples both returned HTTP 206 successfully. The entire video was not downloaded in this check.
- Both release workflows run engine and Android tests before building signed APKs.

After updating, paste the Bilibili link again and open its format list to fetch fresh playback data. Please verify the complete download on your connection.
