# KirinYT 1.9.5.6 Beta

Pre-release · 24 October 2026 (MYT)

## Bilibili: recover missing page metadata

- Fix `Unable to extract initial state` when Bilibili returns a page shell without `window.__INITIAL_STATE__`. Use the signed video-details API to recover verified video metadata, then continue through the existing format and download logic.
- Recognize localized video paths such as `/en/video/` and `/zh-Hans/video/`. Preserve the requested video part, canonical BV ID, uploader, tags and existing playlist behavior.
- Keep Bangumi redirects and explicit login, unavailable-video and risk-challenge handling. Rejected or incomplete API responses stop with an expected error; mismatched video metadata is rejected.
- Retain the 1.9.5.5 bounded HTTP ranges, partial-file resume, CDN backups and explicit downloader settings.

## Validation

All 42 Python engine regressions passed on yt-dlp `2026.8.19` and `2026.10.21`. Twelve new cases cover the missing-state failure, localized routes, selected parts, legacy AV URLs, playlists, Bangumi redirects, API failures, wrong video metadata and extractor reuse. The release workflow also runs the Android recovery/format tests and verifies APK signatures before publication.

Live metadata extraction succeeded for `BV1kGpv6hEDv?p=1`, returning its title and 15 audio/video formats after the original page returned HTTP 200 without initial-state metadata. The full concert transfer has not been attempted, so download completion still requires an on-device check. The Android `linker` warning shown before the extractor error is separate from this page-metadata failure.

Related upstream report and proposed API approach: [yt-dlp #17894](https://github.com/yt-dlp/yt-dlp/issues/17894) and [PR #17898](https://github.com/yt-dlp/yt-dlp/pull/17898).
