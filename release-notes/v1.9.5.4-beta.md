# KirinYT 1.9.5.4 Beta

Pre-release · 15 October 2026 (MYT)

## Bilibili: recover before downloading the remaining stream

The reported native download of `BV16m421g7iL?p=1` selected `30077+30280` (HEVC video, 1.59 GiB). The primary video response repeatedly ended early, but yt-dlp then spent time downloading and retrying audio before returning control to CDN recovery. The backup was reached and also suffered video read timeouts. This report does not support the earlier explanation about a larger H.264 file.

- Add `--abort-on-error` to Bilibili download recovery. Once a stream exhausts its retries, return immediately to the existing recovery loop instead of downloading the remaining stream on that failed attempt.
- Refresh extraction and select an API-provided backup under the existing retry limit. Resume existing partial downloads using the selected downloader's normal handling. If all attempts fail, report the failure without proceeding through another audio transfer.
- Preserve selected format IDs, downloader preference, rate settings and retry limits. Metadata extraction and downloads from other sites keep their existing error policy. Explicit custom command overrides retain their existing precedence.

## Validation

- 22 Python engine tests, including two new local HTTP regressions for interrupted responses and HTTP 503. They verify that audio is not requested after the failed video attempt, recovery completes the original video bytes, and FFmpeg produces a file containing both streams. The previous completed-audio/resume regressions remain enabled.
- 23 Android unit tests cover Bilibili recovery and format recommendation, including the native incomplete-response diagnostic and unchanged requests for other sites.
- Release workflows run both suites and verify all APK signatures before publication.

This change removes avoidable waiting before failover. It does not establish why the public CDN connection slowed down or guarantee a faster backup server. The reported public transfer has not been reproduced on the user's network; previously incomplete or frozen files are not repaired by installing this update.
